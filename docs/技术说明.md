## 架构

```text
┌────────────────────────────┐
│          Vue 3 UI          │  设置界面 / 悬浮窗渲染 / 穿透小控件 / 状态
└─────────────┬──────────────┘
              │ Tauri IPC（命令 + 事件）
┌─────────────▼──────────────┐
│         Rust Core          │
│  douyin: resolver/sign/    │
│  signer/ws/parser/proto/   │
│  login/event               │
│  tts: 队列 + Edge TTS      │
│  gift / welcome            │
│  state / commands /        │
│  connection / window /     │
│  config                    │
└─────────────┬──────────────┘
              ▼
   WebView2（签名页）+ 登录子进程（独立 WebView2）+ Windows API（窗口 / 托盘 / winmm / DPAPI）
```

**弹幕事件流**：抖音 WS → `douyin::ws` 解帧 → `parser` → 事件分流

- `Danmaku` → `state::record_danmaku`（速率统计）+ `tts::on_danmaku`（朗读，独立筛选）+ `emit("danmaku")` → Overlay 渲染（前端再做一遍显示筛选）
- `Backing` → `gift::on_backing`（门槛 + 连击合并 → `emit("gift")`）+ `tts::on_backing`（礼物朗读，独立门槛与聚合）
- `Welcome` → `welcome::on_welcome`（去重限速 → `emit("welcome")`）

**连接流程**（`connection.rs`）

1. `connect_room(web_rid)`：校验数字 / 字母（直播间号是数字长串，抖音号可带字母，实测 `88866kzi` 也能连）→ 状态机置 `Connecting` → 起任务
2. `resolver::resolve`：`GET live.douyin.com/{短号}` 取 `ttwid` → `enter` 接口取 `room_id`、主播名、开播状态（**只带 ttwid**，带登录态会把网页端的观看会话顶掉）→ 给 WS 的 cookie = 登录态 + ttwid（**必须保留 ttwid**）
3. 存入最近房间（含主播名）→ 生成一次 `user_unique_id`（整条连接复用）
4. 会话循环：`ws::run_ws_session`（签名 → 握手 → 10s 心跳 → 收帧 / 回 ack），出错按 `WsError::retryable()` 决定是否退避重连
5. 收尾：仅当自己仍是当前连接任务（取消令牌未被换走）才重置状态，避免旧任务误清新连接（`finish_connection`）

**连接状态双通道**：主窗口订阅 `room-status` 事件；悬浮窗额外每 2s 轮询 `get_connection_status` 兜底防事件丢失。

## 协议层实现要点

### 签名（`douyin/sign.rs` + `signer.rs`）

- 签名输入 = **13 个参数**（`SIGN_PARAM_ORDER`，顺序不可改）拼 `k=v` 用逗号连接 → MD5 小写 hex（= `X-MS-STUB`）→ webmssdk `getSign` → `X-Bogus`
- 必须跑 JS：隐藏窗口 `sign` 加载 `sign.html`（内含 `douyin-sign.js`），Rust 侧 `eval` 触发、页面经 `invoke('douyin_sign_reply')` 回包、`oneshot` 按 id 路由（Tauri 的 `eval` 拿不到 JS 返回值）
- 页面未就绪回 `NOT_READY` → Rust 内部重试 10×200ms；单次等待上限 3s
- 启动自检跑一次固定 stub，日志里能看到 `[sign] WebView2 签名自检通过：X-Bogus=…`

### WS 会话（`douyin/ws.rs`）

- URL 参数与顺序照探针实测（`build_ws_url`），`internal_ext` 必须 `encodeURIComponent` 转义
- 握手头：`User-Agent` + `Origin: https://live.douyin.com` + `Cookie`（含 ttwid）
- 收到帧：`decode_push_frame`（f8 是 gzip 的 `Response`）→ `decode_response` → 逐条 `parser::parse` → `need_ack` 时回 `PushFrame{f2=log_id, f7="ack", f8=internal_ext}`
- **解不开的帧只记日志、不中断会话**（抖音会夹带格式异常的帧）

### 登录（`douyin/login.rs` + `douyin/login_helper.rs`）

登录页跑在**独立子进程**里（同一个 exe，`douyin-danmu.exe --login-helper`）：抖音首页是重度 SPA，会自动播放视频流，让 WebView2 的 GPU 进程峰值到 1 GB 上下；窗口销毁后还有约 84 MB 的 GPU 缓存残留（进程级，要等系统内存压力才回收）。子进程退出是唯一能确定全额归还内存的方式，主程序全程不加载抖音首页。

- 主程序 `commands::douyin_login_open` spawn 自己（参数 `--login-helper`）并等它退出；helper 把结果写成 stdout 上的一行 `LOGIN_COOKIE=<cookie>`，父进程解析后照旧 DPAPI 落盘
- 为什么走 stdout 不走 config.json：主程序每 2 秒在 flush overlay 位置，两个进程同时改写同一个 config.json 会互相覆盖；而且管道不落盘，明文 Cookie 不会留在磁盘上
- helper 用**独立的 WebView2 目录**（`%LOCALAPPDATA%\com.douyindanmu.app\login-webview`）与**独立日志**（`douyin-danmu-login.log`）：WebView2 不允许两个环境共用同一个 user data folder，两进程写同一日志文件会互相截断
- 窗口 1180×820 / 最小 1000×680（**不能更窄**：抖音页面窄视口下会把登录入口整个藏起来），并关掉自动播放（`--autoplay-policy=document-user-activation-required`，否则一打开就出声）
- 每 1 秒读一次 `WebviewWindow::cookies()`，出现 `sessionid` 即视为成功 → 只保留抖音域下的 cookie → 交给主进程落盘
- 5 分钟超时；用户关窗视为放弃（退出码非 0）。退出登录删掉整个 `login-webview` 目录

## 字段与语义（实测）

| 内容 | 字段 | 备注 |
|---|---|---|
| 弹幕正文 / 昵称 | `WebcastChatMessage` f3 / `User.f3` | `Common.createTime` 是**毫秒** |
| 用户等级（荣誉等级） | `User.f23 = PayGrade` → `f6` | 回退：递归抠图标 URL 里的 `new_user_grade_level_v1_N.png` |
| 粉丝团（灯牌）等级 | `User.f24 = FansClub` → `f1 = FansClubData` → `f2` | 消息里**没有**灯牌名 |
| 礼物名 / 钻石价 | `WebcastGiftMessage` f15 = `GiftStruct` → f16 名 / f12 钻石价 | 1 钻石 = 0.1 元（**未与真实账单核对**） |
| 礼物数量 | `f6 = combo_count` | **累计值**，直接采用 |
| 进场 / 关注 / 点赞 | `WebcastMemberMessage` / `WebcastSocialMessage` / `WebcastLikeMessage` | 点赞的 `LIKE` 事件里 user 在 f5 |
| 表情弹幕 | `WebcastEmojiChatMessage`：f3 = emojiId、f5 = `defaultContent`（表情名） | **独立消息类型**（不是 `ChatMessage` 的字段）；名字取不到时退回 f4 `emojiContent` 的 `defaultPattern` / `key` |
| 表情弹幕（正文形态） | 不带表情字段的 `[名字]` 文本，混在 `WebcastChatMessage` 正文里 | 实测「[发呆][发呆]」：网页端把表情当文本发。识别与剥离在 `douyin::emote::strip_bracket_emotes`；朗读默认剥掉 `[名字]` 只念剩下的文字（代价：手打的方括号也会被剥） |
| @提及 | `WebcastChatMessage` 正文开头的 `@名字`（真机「@神秘人六阶 谢谢哥」） | **没有独立的回复消息类型**（探针 method 列表里只有 `ChatMessage`），按正文形态认（`douyin::mention::split_mention`）：名字到第一个空白/不可见字符为止；朗读念成「发送者对被提及者说 正文」 |
| 真实 room_id / 主播名 / 开播状态 | `enter` 响应 `data.data[0].id_str` / `data.user.nickname` / `data.data[0].status`（2=直播中，4=已结束） | 该请求**只带 ttwid、不带登录态**（见下） |
| 账号观看会话 | 同一账号 + 同一直播间**只保留一个**：手机端 / 网页端 / 助手互相会顶 | 带登录 Cookie 调 `enter` 会把网页端顶掉（弹「账号已在其他地方进入直播间」）；匿名调它啥也不少，登录态只交给 WS（礼物必需） |
| 关注在播 | `POST https://www.douyin.com/webcast/feed/follow_top/`（www 关注页「正在直播」块原样接口）：body `source_key=web_homepage_follow_top&follow_session_id=<游标>` | **不需要签名**（`a_bogus` / `msToken` / `uifid` 全可省）；`data[].owner.nickname` / `web_rid`（直播间短号）/ `data.id_str`（room_id）；翻页在 `extra` |
| 「我的直播间」（自己，排关注在播首位） | `GET https://www.douyin.com/aweme/v1/web/user/profile/self/`（只带登录 Cookie）→ `user.uid` / `user.nickname` / `user.unique_id`（**抖音号**）/ `user.room_id_str` | **不需要签名**；同一套字段在 `profile/other/?sec_user_id=` 里（**匿名也能查别人**，开播中 `room_id_str` 就是真实 room_id）。自己那条用抖音号走既有连接流程：`enter` 认**抖音号**（`data.user.id_str` 与 `uid` 一致），但**不认 uid、也不认 room_id**（都回 `4001038`）。`room_id_str` **未开播就归 0**（实测：已下播的号也是 0）→ 当不了「有没有房间」的判据，所以这条不看开播状态 |

**坑**：`User.f6` **不是**用户等级 —— 绝大多数用户不带这个字段，带的人值是 1。真机曾因为它显示错等级。

## 配置与数据

- 配置目录：`%APPDATA%\com.douyindanmu.app\config.json`
- 保存内容：登录 Cookie、Overlay 样式与位置大小、弹幕过滤（等级门槛 + 敏感词）、TTS 配置（开关/音色/语速/音量/文案开关/队列上限/朗读筛选）、礼物列表配置（开关/门槛/条数/合并窗口）、礼物朗读配置（开关/门槛）、欢迎信息开关、进场欢迎语音播报开关、最近房间列表（上限 10）
- 登录 Cookie 落盘前经 **Windows DPAPI 加密**（绑定当前用户与机器）：配置文件拷贝到其它机器/账户无法解密，需重新登录
- 数据仅存本机，不收集遥测、不上传日志
- 例外：开启朗读后，弹幕正文 / 打赏文案会发往微软 Edge TTS 服务合成语音；关掉开关即停（音色列表刷新同样访问该服务）

## 统一日志

`tauri-plugin-log` + `log` 门面宏，配置只在 `lib.rs` 的插件注册处一处（唯一配置点）。

- 落盘：`%LOCALAPPDATA%\com.douyindanmu.app\logs\douyin-danmu.log`（Tauri 的 LogDir 在 Windows 上是 LocalAppData）；关于页「日志」按钮用资源管理器打开
- 轮转：5MB + `KeepSome(7)`（插件默认 40KB + KeepOne，必须显式覆盖）；时区显式 `UseLocal`（默认 UTC 会差 8 小时）
- 输出目标：release 只挂 `LogDir`（`windows_subsystem = "windows"` 没有可写的 stdout），dev 额外挂 `Stdout`
- 登录子进程另写一个文件：`%LOCALAPPDATA%\com.douyindanmu.app\logs\douyin-danmu-login.log`（两进程写同一文件会互相截断）
- 业务前缀：`[douyin]`（连接/签名/会话）、`[sign]`（签名器自检）、`[login]`、`[tts]`、`[config]`、`[overlay]`、`[tray]`、`[live]`（关注在播）、`[emote]`（表情弹幕）
- 安全：日志里不得出现完整 Cookie（`config.rs` 的 Cookie 解密失败只打原因，`crypto.rs` 的 Err 串只含字节长度与 `last_os_error()`）
